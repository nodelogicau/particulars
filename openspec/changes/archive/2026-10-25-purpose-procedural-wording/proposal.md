## Why

*Purpose* defines procedural memory as "how an agent does things", and puts it in skills and prompts. Every other memory type in that section is described by what it holds for the person. Semantic memory is what is believed. The prospective layer is what a person means to do. Procedural memory alone is the agent's. That is the harness's know-how, not the person's, and it frames the whole family as agent memory when its purpose is to serve the person.

The [Forgetting](https://github.com/nodelogicau/forgetting) whitepaper, which grew out of #35, now argues the human case. For a person, procedural memory is practised skill and habit, which is already ready-to-hand and needs no store to withdraw. What a person needs kept outside is the reason behind a habit, and the record of how a rare procedure was done last time. Agent skills are delegation: real, but a different thing. *Purpose* should not contradict that argument, and should point to it.

## What Changes

- ***Purpose*'s third paragraph** describes procedural memory in human terms, as know-how: the habits and practised skills a person exercises rather than recalls. It stays outside the format.
- **A harness's own know-how** is still named as living in skill files and prompts, and a workspace's conventions document still addresses an agent without constraining anything. Neither is presented as the definition of procedural memory.
- **Episodic memory's wording is unchanged.** It is still an event that may be a particular, with a log of episodes not DKF's job.
- ***Purpose* points to the whitepaper** for why the family models memory as several kinds, and what each is for.
- ***References* gains an entry** for the whitepaper.

Not **BREAKING**: prose only, with no normative change to any object, field, tool or rule.
